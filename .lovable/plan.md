### TypeScript check with **strict** flags forced on: 89 errors
The project intentionally ships with `strict: false`, `strictNullChecks: false`, `noImplicitAny: false` in both `tsconfig.json` and `tsconfig.app.json`. When I force `--strict --strictNullChecks --noImplicitAny`, ~89 messages surface. Almost all are null-vs-undefined coercion noise that won't crash at runtime. A handful, however, are real risks.

I sorted them into three buckets:

**Bucket A — Real runtime-crash risk (fix)**
| File | Issue |
|---|---|
| `src/components/maintenance/NewWorkOrderSheet.tsx:145,382-397` | `useState` initialized as `undefined` is being treated as `never` later — `selectedTruck.id`, `.unit_number`, `.model` will throw `Cannot read properties of undefined` once the form opens with no truck preselected. Real bug. |
| `src/pages/Finance.tsx:378` | Two `Object is possibly 'null'` dereferences inside a numeric expression — will throw at runtime if either side is null. |
| `src/components/settings/AuditLogPanel.tsx:55,62` | `user_id` can be `null` but is passed into `.in([...])` and used as an object index, producing `undefined` keys. |
| `src/components/driver/MonthlyBonusWidget.tsx:6` | `canvas-confetti` has no type declaration. Not a crash, but it's silently typed as `any`. Add a one-line `.d.ts` shim. |

**Bucket B — RLS / data-integrity risk (fix)**
| File | Issue |
|---|---|
| `src/components/finance/ReconciliationPreview.tsx:218` | Building an expense insert with `org_id: orgId` where `orgId` can be `null`. Insert will be rejected by RLS or, worse, succeed with no org_id. Should bail or use the authenticated user's org. |

**Bucket C — Cosmetic null/undefined coercion (defer)**
The remaining ~75 errors are all `string | null` (DB column) being passed where `string | undefined` is expected, or `driver?.id` (undefined) being passed to a fetcher that's already guarded by an `enabled` clause in TanStack Query. They don't crash today because the surrounding `useQuery({ enabled: !!id })` patterns prevent the call from firing. Fixing them requires either flipping the project to strict mode (large refactor across ~30 files) or sprinkling `??` / non-null assertions site-by-site, which adds noise without changing behavior.

## Plan

1. **Add `src/types/canvas-confetti.d.ts`** with `declare module 'canvas-confetti';` to remove the implicit-any.

2. **Fix `NewWorkOrderSheet.tsx`** — type the `selectedTruck` state explicitly (`Truck | null`) instead of relying on inference that resolves to `never`, and null-check it before reading `.id`/`.unit_number`/`.model`.

3. **Fix `Finance.tsx:378`** — add a null guard around the math expression (return `0` or skip the row if either side is null).

4. **Fix `AuditLogPanel.tsx`** — filter out rows with null `user_id` before passing the ID list into `.in(...)` and the lookup map.

5. **Fix `ReconciliationPreview.tsx`** — bail early if `orgId` is null (toast the user) so we never POST a half-populated row that fails RLS.

6. **Document Bucket C as known/intentional** in code comments only where the lint is most surprising; do **not** flip the project to `strict: true` in this pass — that's a separate, larger refactor and not what the user asked for.

### Out of scope
- Migrating the entire codebase to `strict: true` / `strictNullChecks: true`. Happy to do this as a follow-up if you want, but it touches ~30 files and changes no runtime behavior.
- Regenerating `src/integrations/supabase/types.ts` — already perfectly in sync.
